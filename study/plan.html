01 · Why this projectExam domains

The exam is almost entirely about building agents, tools, and MCP servers — not about polished chat UIs or web deployment. A browser toy (this repo's usual shape) would be a poor fit, which is why this project is a local Node project instead. Weights below are from public prep sources.

Sources: freeCodeCamp, dev.to, claudecertificationguide.com
DomainWeightCovers
Agentic Architecture & Orchestration 27% The full agent loop: gather context → take action → verify
Claude Code Configuration & Workflows 20% Local environment setup, the Claude Agent SDK, authentication, multi-agent architectures
Prompt Engineering & Context Management 20% Structured JSON outputs, error handling, multi-pass review loops, large-context strategies
Tool Design & Model Context Protocol (MCP) 18% Designing tools, building/consuming MCP servers
Context Management 15% Token budgets, compaction, prompt caching

Confirmed Agent SDK config surface

  • systemPrompt — omit, { type: "preset", preset: "claude_code", append: "..." }, or a custom string
  • allowedTools / disallowedTools — tool names, mcp__server__tool patterns, globs
  • permissionMode — six values: default, dontAsk, acceptEdits, bypassPermissions, plan, auto
  • hooks — 30+ events including PreToolUse / PostToolUse, matcher-based callbacks
  • mcpServers — stdio ({command, args, env}), remote (http/sse), or in-process via createSdkMcpServer
  • agents — subagent definitions (also loadable from .claude/agents/*.md)

03 · Locked inDecisions already made

Scope & shape Local Node project, no web/Vercel deployment (the exam doesn't test deployment) · full scope, not a stripped-down subset.
MCP SDK version @modelcontextprotocol/sdk v1 — stable and fully verified, including an in-memory transport for zero-subprocess tests. v2 exists but its API shape wasn't reliably verifiable this session, so it's deferred rather than guessed at.
Other service One local MCP server — no external account needed.
Default model for lab runs Sonnet 5 for day-to-day iteration; swap to Opus 5 for an occasional polished run.
Testing claude-architect-lab/tests/ is a second, independently conventioned tests/ directory (plain node:test, no jsdom, no HTML page) — kept unregistered in the root tests/run.mjs SUITES array.

06 · Watch for theseKey implementation notes

  • API key: .env inside claude-architect-lab/, already covered by the root .gitignore's bare .env/.env.* patterns. Loaded via Node's built-in process.loadEnvFile() — no dotenv dependency.
  • Minimal dependencies: @anthropic-ai/sdk, @anthropic-ai/claude-agent-sdk, @modelcontextprotocol/sdk, zod (MCP tool schemas). No separate JSON-schema validator — output_config.format and MCP schemas already cover it.
  • run-lab-tests.mjs must shell out to this package's own node --test, never the root tests/ suite — the root harness is jsdom/page-shaped and unrelated to this project.
  • Not a browser toy: this project is not linked from index.html, and CLAUDE.md's "verify the live deployed site" rule does not apply to it.
  • No live API calls in automated tests: loop/logic tests stub Messages.create; sdk-version/agent.mjs's true end-to-end behavior is manual-run-and-eyeball only, same spirit as battle-bots-v2.core.test.mjs.

07 · When it's time to buildNext-steps checklist

  1. cd claude-architect-lab && npm install
  2. npm test — every suite passes with zero network calls
  3. Manually run each milestone against the real API with ANTHROPIC_API_KEY set: agent-loop.mjs, mcp-server/server.mjs (+ a client run), structured-output.mjs, review-loop.mjs, context-budget.mjs (confirm before/after token counts for both compaction and caching), orchestrator.mjs, sdk-version/agent.mjs (confirm the hook fires and the MCP tool is reachable)
  4. Re-check npm view @anthropic-ai/claude-agent-sdk version immediately before implementation, given how fast that package ships
  5. Read the finished README top to bottom as a study session — for each row in the exam-domain table, confirm the file actually demonstrates the concept, not just that it runs
