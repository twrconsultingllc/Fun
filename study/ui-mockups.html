Claude Architect Lab · speculative product UI

Three UI mockups for the same concept

usecase.html pitches a five-assistant product — Research Assistant, Client Tracker, Checklist Builder, Second-Look Reviewer, Memo Writer — for a licensing consulting firm. This page collects three genuinely different, clickable mockups of what a real UI for that product could look like, built purely to compare interaction models. Each one runs the same scripted example — Meridian Payments expanding from California and New York into Texas, Florida, and Illinois — through the same five-step pipeline, so the only thing that varies between them is the interaction design, not the underlying story.

Read before clicking around Every page linked below is a static, client-side prototype: all client and state data is fictional sample data, the "pipeline run" is scripted with setTimeout, and nothing is saved, sent anywhere, or backed by a real agent or API call. This is a different, more speculative exercise than ui-plan.html, which walks through what the real CLI lab's agents and LLM calls actually do internally — the gather/act/verify loop, retries, review chains, compaction, caching, and delegation — rather than imagining a UI for them. Nothing on this page or its three linked variations is built for real.
Variation A

Chat

A single conversational thread. Ask a plain-language question, and the five assistants hand off one at a time as chat bubbles, ending with the reviewed checklist and memo inline in the conversation.

One shared color palette and type system, so the comparison below is about structure and interaction, not visual polish — plus the same five-assistant pipeline, the same three sample clients, and the same scripted Meridian TX/FL/IL scenario as the one fully wired-up example in every variation.
