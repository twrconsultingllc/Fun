Pattern Lab · 01 / 04 · CSS scroll-driven animation + View Transitions

Scroll Transit

Every animation below is declared in CSS and driven by the browser's own scroll and view timelines — nothing here runs on a requestAnimationFrame loop. The grid at the bottom uses the View Transitions API to morph the DOM between states instead of a JS transition library.

animation-timeline: view()

This shape's keyframes are scrubbed by how far it has travelled through the viewport, not by elapsed time. Scroll past it slowly and it barely moves; scroll fast and it still lands exactly in sync.

animation-range

animation-range: entry 0% cover 45% tells the browser exactly which slice of the element's journey through the viewport maps to the animation's 0%–100%.

No JS per frame

There is no scroll event listener anywhere on this page. The compositor thread updates these animations independently of the main thread, which is why they stay smooth even while other JS is busy.

Graceful degradation

If your browser doesn't support scroll-driven animation, or you have reduced motion turned on, every shape above rendered fully visible immediately instead of sitting invisible at its 0% frame.

Now try View Transitions

Click any swatch to promote it into the featured slot above the grid, or shuffle the whole set. Either action mutates the DOM directly — the only difference with support is that the mutation is wrapped in document.startViewTransition() so the browser animates the change for you.
