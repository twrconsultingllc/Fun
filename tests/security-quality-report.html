01Security

No exposed secrets or API keys anywhere
Not an issue
The Gemini key is read from process.env.GEMINI_API_KEY server-side only in both battle-bots/api/get-actions.js and battle-bots-V2/api/get-actions.js, sent via header, and scrubbed from error messages before they reach the browser. No .env was ever committed, in history or working tree. Confirmed clean — nothing to fix.
Open proxy / cost-abuse risk on the battle-bots API endpoints
Fixed
battle-bots-V2/api/get-actions.js and the V1 equivalent had no rate limiting, auth, or origin check, and accepted an arbitrary client-supplied model name — anyone with the deployed URL could burn the owner's Gemini quota.
Fixed: added three server-side guards to both apps — a client-requested model is only honoured if it's actually in Google's live model catalog (cached 5 min); every field that reaches the prompt (gameState, prompt/promptA/promptB, memory) is now size- and shape-checked before use; and requests without a same-host Origin/Referer are rejected with 403. Verified live on both funv2.vercel.app and fun-xi-rouge.vercel.app — a spoofed cross-site Origin now returns 403, and malformed payloads return a specific 400 instead of reaching Gemini.
commit 9b582bd — "Harden battle-bots API endpoints against quota abuse"
Real rate limiting (a hard cap on requests/minute) is intentionally not included — it needs an external store (e.g. Upstash Redis) and a new dependency, which is a separate decision still pending on the user's side.
Real XSS bug in battle-bots V1
Open
battle-bots/public/game.js's addLog() injects LLM-derived text into innerHTML unescaped, and the server doesn't whitelist the skill field before passing it through. battle-bots-V2 already fixed both (an escapeHtml() helper in ui.js and a strict SKILL_CATALOG whitelist server-side). Recommend porting V2's fix back to V1, or retiring V1 in favor of V2.
No Subresource Integrity on pinned CDN scripts
Fixed
three.js, gsap, ScrollTrigger, crypto-js and font-awesome were all loaded from cdnjs at a pinned version but with no integrity attribute — a compromised CDN could have silently served different code.
Fixed: added integrity="sha512-…", crossorigin="anonymous" and referrerpolicy="no-referrer" to all 10 affected tags across index.html, race-day.html, ai-swarm.html, threejsGallery.html, secret.html, 51d6d17b…html and tricalc.html. Hashes were pulled from cdnjs's own published SRI metadata and cross-verified by independently downloading and hashing each file. Verified live on the deployed GitHub Pages site. cdn.tailwindcss.com (in bots.html/tricalc.html) is intentionally left alone — it's a JIT compiler with no fixed file to hash.
commit a10bf6f — "Add Subresource Integrity and no-referrer policy to pinned CDN assets"
No security headers configured (CSP, X-Frame-Options, etc.)
Open
No vercel.json exists for either battle-bots deployment, so there's no Content-Security-Policy, X-Frame-Options, or similar — everything relies on platform defaults.
No root-level .gitignore
Open
Currently harmless (nothing stray is tracked), but a future root-level node_modules or .env wouldn't be excluded by default. Both battle-bots subdirectories already have correct .gitignore files.
Deprecated Gemini SDK
Open
@google/generative-ai (used by both battle-bots apps) is Google's deprecated Gemini SDK, superseded by @google/genai. Not a vulnerability, just worth migrating eventually.
