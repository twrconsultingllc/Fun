Review #65 — J.A.R.V.I.S. Session 13: knowledge pack

Ask the test copy "tell me about Peru" and it spins the globe to Peru and reads stable public facts. "How far is Mars" opens the solar system near Mars, and "tell me about the Mark 42" opens the suit schematic, with the line marked as fan knowledge. The facts come from a pack built by a script in the repo from NASA, JPL, the Yale Bright Star Catalogue, PubChem and the CIA World Factbook. The page copies the pack into its own database the first time you ask.

01Security and privacy

Head block and CSP unchanged
Confirmed clean

git diff of jarvis-test.html touches no <meta> line except the description. The suite still pins the whole CSP string to what it was before Session 8, so connect-src 'self' stands. The pack is fetched from jarvis/knowledge/pack.json on this site. In Chromium, the request log showed exactly one request for it, from the page's own origin, and nothing from jarvis/knowledge/ before the first question.

Every record goes in through save(), checked by fits()
Confirmed clean

The one-place-that-saves checks pass unchanged: no localStorage write anywhere in the page, exactly one 'readwrite' transaction, in flush(), only save() queues a write, and save() calls fits() before queueing. installPack() writes the records with save('pack', key, record) and the version with save('meta', 'pack', n). Nothing else writes the table.

The pack table can hold only pack records
Confirmed clean

fits('pack', …) takes a record only if it has exactly its kind's fields (one of seven kinds), each of the right type, under its own key (country:peru), with a suit only when fan is true, and at most 2,000 records. The suite tries a setting, a usage count, a protocol, a record under the wrong key, an extra field holding a phone number, an unmarked suit line, an unknown kind, markup, personal text, a phone number, a missing field and text where a number belongs. All are refused. The scrub drops a stale field, a stray note and a record under the wrong key from a seeded database on load. meta takes the pack version only as a whole number.

No markup and no link markers in a fact
Fixed

Fact text reaches the chat through the same add() path as every answer, which builds text nodes, and the page still has no innerHTML. A command link (⟦label|command⟧) only becomes a button for a command the page already lists. Even so, a fact has no reason to carry the markers. A pack file that did could have put a link to a listed command, such as "forget my name", inside a fact.

Fix: Both the page's packText() and the build's textOk() now refuse <, >, ⟦ and ⟧, and the suite tries a marker in a flag description.
Nothing personal; counted by kind, never by name
Confirmed clean

Every text field passes the same personal() test as settings. The build carries a copy of PERSONAL, and the suite checks that the two lists are identical. A question counts once under one of seven fixed IDs (cmd:know-country … cmd:know-suit), from KNOW_IDS. No usage ID or saved count contains the name asked about. The suite checks Peru, and one of the deliberate breaks (counting by name) failed four checks.

Not in a backup or a settings code; "what do you save" says it's there
Confirmed clean

backupData() reads only the kept settings, the protocols and the counts. The suite confirms that a backup made after the pack is loaded has no pack key and none of its text. Before the pack is loaded, "what do you save" says it will be copied in when first asked. After that, it gives the number of public facts kept and says none of them is about you. Without IndexedDB it says the pack is in memory for this visit only.

The build script
Confirmed clean

jarvis/knowledge/build.mjs has no dependencies (Node 22's own fetch and zlib). It fetches only a fixed list of https sources, with the Factbook archive pinned to commit 144d6977b2b01ac1cbd220de754c0a005616760b. It writes only pack.json beside itself, or the --out path given on the command line, and only when the version changes. Every parser cross-checks its source: a star's catalogue name must match its HR number, a mission page must name the craft and its ID with a launch year matching the ID, a country file's own short name must match, a moon's radius must be within 15% of a rough value, and every number is range-checked. A pack with fewer records of a kind than expected is refused, so a half-built pack is never written.

The workflow
Confirmed clean

.github/workflows/jarvis-knowledge.yml runs only by hand (workflow_dispatch), uses the same SHA-pinned actions/checkout and actions/setup-node as the Daily Wire workflow, keeps no token in git config while the build runs (persist-credentials: false), and hands GITHUB_TOKEN only to the final commit step. No event data is interpolated into a shell line. It builds from the samples first, then from the real sources, checks the result, and commits only jarvis/knowledge/pack.json.

02Code quality

The real pack isn't committed: its sources are blocked here
Open

The container's proxy refuses NASA, JPL, CDS and PubChem (CONNECT 403, the same as the Daily Wire's feed hosts). As asked, no pack built from anything else was committed. Until the workflow runs, the live test copy answers a fact question with "My knowledge pack isn't on this site yet", which the suite pins, and every other answer is unchanged. To fix: run "J.A.R.V.I.S. knowledge pack" from the Actions tab, or node build.mjs in the Codespace. Only the Factbook archive was reachable from here.

NASA and JPL page layouts are reconstructed, not copied
Open

The planet and moon samples use the real values (from a dataset scraped from those pages) in the layout those pages are known to use, and the mission pages are minimal stand-ins. The parsers read tables by their header and row labels, not by fixed positions, and fall back to positions for the moon table. If the real layout differs, the build stops and names the page; it never writes a half-built pack. Open until the first real run passes.

Stable facts only, enforced on both sides
Confirmed clean

STALE_KEY (field names) and STALE_TEXT (words such as population, GDP, president, currency, "est.", "currently", "number of moons") are the same in the page and the build, and the suite compares them. A record with a population, GDP, moon-count or leader field, population in words, an estimate, or "currently" in a suit line is refused by both. A pack carrying one fails checkPack(). No field in PACK_FIELDS has such a name. The build lists its sources, and none is Wikipedia.

A parallax read as 375 instead of 0.375
Fixed

The star catalogue writes parallax as +.375, and the number reader needed a digit before the point, so it read 375 and put Sirius at 0.0 light years. It was caught by reading the dry-run output, not by a check, which is the reason for the fix below.

Fix: num() reads a leading-point number, the build range-checks each distance (4 to 55 light years), and the suite pins Sirius at 8.7 and Betelgeuse at none.
"est." could never match
Fixed

In \b(?:…|est\.|…)\b, the closing word boundary needs a letter after the full stop, so "(2024 est.)" passed. The suite's "an estimate is refused" check caught it on the first run.

Fix: est\. now sits outside the word-bounded group in both copies.
A fact sentence longer than speech allows
Fixed

speechChunks() joined whole sentences up to 160 characters, but left a single longer sentence whole. A flag description can be 240 characters, which is over the roughly 15 seconds after which Chrome silently stops speaking.

Fix: A sentence over 160 characters is now broken at semicolons, then commas, then spaces. Peru's answer is spoken in three parts. Shorter answers are unchanged, and the existing speech checks pass.
A missing answer spoken as "null"
Fixed

The suite's existing check that "how far is the moon" is said in miles failed. The Moon's record deliberately hands that question back to the older chat answer by returning null, but inUnits(null) turned it into the text "null".

Fix: The answer is checked before units are applied.
Every country is one the globe can find
Confirmed clean

All 76 countries in the pack are PLACES keys. Every country on the globe is in the pack apart from England and Scotland, which the Factbook covers as the UK. Each one opens the globe on itself (checked for Peru, the United States, DR Congo and Australia). In Chromium, the globe's stat line read PERU · 9.2°S 75.0°W at both sizes.
