02Code quality & accessibility

The help answer was cut off when spoken
Fixed

The user didn't hear the new features when asking Jarvis what it can do on the test page. The deployed main had the right text, so the push wasn't the problem. Each answer was spoken as one utterance, and Chrome stops a single utterance after about 15 seconds. The help answer is about 90 words, roughly 35 seconds, and the new features start about halfway through. say() now sends the answer as several utterances, using a new pure function, speechChunks: whole sentences only, at most 160 characters each, so about 10 seconds. The help answer becomes 5 pieces of 79 to 140 characters. The orb shows SPEAKING from the first piece to the last. A counter (sayGen) stops pieces cancelled by a newer question from switching it back to STANDBY. The chat log still shows the answer as one message. The bug was in both pages, so both are fixed in this change, as CLAUDE.md asks.

Only two ways of asking for help worked
Fixed

Only "what can you do" and "help" got the list. "What else can you do", "tell me what you can do", "what can you show me" and "list your commands" got a fallback. "What are your features" got the "who are you" answer, and "Hey Jarvis, what can you do?" got a greeting, because the greeting rule came first. The help rule now matches all of these and is checked before greetings and "who are you". Plain "hello" still gets a greeting.

Tested with a speech engine that behaves like the real one
Confirmed clean

Both suites gain a "Speaking long answers" section, with 23 checks each: jarvis-test 287 (264 before), jarvis 151 (128 before). The fake engine queues on speak(). It calls onstart/onend only when the test says, and cancel() reports each dropped utterance as an error asynchronously, as Chrome does (the lesson in CLAUDE.md from the mic fake). The checks: the pieces join back into the exact answer, every piece ends a sentence and is under 160 characters, and the whole answer is queued as several utterances while the log shows it as one message. The orb stays SPEAKING between pieces, and a new question cancels the old pieces without the orb flashing to STANDBY. Seven phrasings get the help answer. The new section crashes against the previously deployed jarvis-test.html, so it does catch the old behaviour.

Not reproduced in a real Chrome voice
Open

Headless Chromium has no speech voices, so the 15-second cutoff itself can't be heard here. The fix is the standard workaround for it, but the proof is the user hearing the full help answer on their own device. Answers in other parts of the page are all shorter than the help answer.
