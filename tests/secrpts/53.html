01Security & privacy

Audit: what was stored
Confirmed clean

A grep of both pages for localStorage, sessionStorage, indexedDB, document.cookie and caches. found only localStorage, under five keys: jarvis-name (the user's name: personal), jarvis-learned (taught phrases in the user's own words: could be personal), and three settings, jarvis-skin, jarvis-voices and jarvis-mic-note. No cookies, no IndexedDB, no session storage. The chat log, the camera, the threat scan and the wake switch were never stored.

One gateway for every save
Fixed

Every write now goes through store(), which accepts only the four keys in STORE_KEYS (the three settings and taught phrases) and refuses any value that personal() flags. That covers emails, phone and ID numbers (7 or more digits), any number of 5 or more digits (zip codes, accounts), dates, street addresses, web addresses, and self-disclosures such as "my name", "my birthday", "my password", "my mom", "I live", "I'm 12" and "call me". Both suites check that the page calls localStorage.setItem in exactly one place and never mentions jarvis-name, so a future feature can't quietly bypass it.

The name is never saved
Fixed

"My name is Tony" now gets "I'll remember that until you close this page. I never save names." The name stays in memory, carrying across skins for that visit (review 52), and is gone on reload. In the test copy, "what's my name" and "forget my name" say the same.

Old data is scrubbed on every load
Fixed

scrubStore() runs before anything else on the page. It deletes jarvis-name and any other jarvis-* key that isn't a setting. It drops taught phrases where either side is personal and keeps the rest. It also removes a setting whose value is personal or over 4,000 characters. It touches only jarvis-* keys, because every page on twrconsultingllc.github.io shares one storage area: the suites plant an other-page key and check it survives. In headless Chromium, with a name and a phrase containing a phone number planted the way an older version would have saved them, both pages deleted both on load, at 1280×800 and 390×844, with no page errors.

Teaching a personal phrase: used once, never saved
Fixed

When the meaning or the phrase you teach looks personal, Jarvis still answers it that once, then says why he won't save it ("…because it has a phone or ID number in it"). Checked in the suites and in Chromium: storage was unchanged afterwards. "What do you save" (also "what do you know about me", "privacy check") reads back what's actually in storage, notes that a name told this visit is only in memory, and says nothing personal is kept.

A pattern filter can't catch everything
Open

personal() matches patterns, so a phrase with personal meaning but no pattern ("beam me up" meaning "the blue house on the corner") would still be saved if taught. The design limits the damage: the only free text that can be stored is a short taught phrase and its meaning, capped at 120 and 200 characters and 200 phrases, readable with "what have you learned" and cleared with "forget what you learned". The filter also errs strict: "my mom" or a 5-digit number blocks saving even when harmless.

02Code quality

The tests that pinned the old behaviour were rewritten, not deleted
Fixed

Two checks in each suite asserted the name was saved ("the name is remembered on this device"). They now assert the opposite, because the user changed the rule, not because the page drifted. Review 52's multi-skin checks now tell the name during the visit instead of planting it in storage. 41 checks were added to each suite. Against the previous jarvis.html, the new suite fails (2 failures and a crash on the missing personal).

The Panthers wake word was the full name
Fixed

Seen in a screenshot: in the Panthers skin the Session 6 switch read "HEY STANLEY C. PANTHER", and the wake word was that whole string, so "Stanley, …" didn't wake him. It now uses the first name ("HEY STANLEY"), with two new checks. Test copy only, since Session 6 isn't in jarvis.html.

Other pages on the site keep their own small settings
Open

A grep of the site found localStorage writes in snake.html (best score, difficulty), daily-wire.html (read-story IDs, theme), trick-or-treat-dash.html (game progress) and tricalc.html (triathlon calculator inputs). None store names, contact details or free text typed as identity. They weren't changed, since the request was about Jarvis. Recorded so a Full Monty review can look again.
