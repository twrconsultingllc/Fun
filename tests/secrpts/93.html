Review #93 — TriCalc: no third-party dependencies

tricalc.html is being given to another site to host. It loaded three things from other servers at runtime: Tailwind's in-browser compiler from cdn.tailwindcss.com, Inter and JetBrains Mono from Google Fonts, and Font Awesome 6.4.0 from cdnjs. All three are gone, and the page now makes no request to any other site.

Review performed 2026-11-20 · scope: tricalc.html, tests/tricalc.dom.test.mjs, and tests/secrpts/90.html–92.html · suites run: node run.mjs --page=tricalc.html (tricalc core and dom: 126 passed, 0 failed; 112 before, plus 14 new checks) · headless Chromium: before/after screenshots at 1280 px and 390 px, every button clicked with the page's real CSP enforced · 7 broken copies, each failing its check.

01Security

Tailwind's CDN script ran unpinned third-party code
Fixed

<script src="https://cdn.tailwindcss.com"> runs whatever that server sends, and it can't carry an SRI hash because its content changes between releases. Tailwind describes it as a development tool, not for production. If it failed to load, the page lost almost all its styling.

Fix: the CSS is now generated once with the Tailwind CLI (tailwindcss@3.4.19, the latest 3.x, which is what the CDN served) and the page's own colour config, and inlined as one <style> block (23.4 KB, MIT licence banner kept). No Tailwind code runs in the browser.
Google Fonts and Font Awesome contacted outside servers on every visit
Fixed

Each visit sent the visitor's IP address to fonts.googleapis.com, fonts.gstatic.com and cdnjs.cloudflare.com. Font Awesome also downloaded its full stylesheet and two icon fonts for the 13 icons used.

Fix: text uses each device's system font (Segoe UI on Windows, San Francisco on Apple, Roboto on Android). The 13 icons are inline SVG, one <symbol> each, using the path data from the same @fortawesome/fontawesome-free@6.4.0 release, so they look the same. Playwright logged every request in the before and after runs: 7 to other sites before (the CDN script, a font CSS file, the icon CSS, two font files, two icon fonts), 0 after.
CSP now allows nothing from outside, and only the page's own script
Fixed

Old policy: script-src 'self' 'unsafe-inline' https://cdn.tailwindcss.com, plus style and font allowances for three CDNs. New policy: default-src 'none'; script-src 'sha256-…'; style-src 'unsafe-inline'; img-src data:; base-uri 'none'; form-action 'none'. The one inline script is allowed by its hash, so an injected script wouldn't run even if a way to inject one were found.

Check: in headless Chromium, with the policy enforced, the page rendered and every button worked, with no console errors and no "Refused" messages. The suite checks that the hash in the policy matches the script.
Inline styles are still allowed
Open

style-src 'unsafe-inline' stays, because the compiled CSS is an inline block and the time-split bar sets widths in style attributes. The risk is low: nothing from the URL or storage reaches markup (next item). Removing it would need a hash for the style block and CSSOM-set widths. That's possible, but it would make the page harder for the other site to restyle.

Share links and saved plans can't inject markup
Confirmed clean

The page builds 9 pieces of HTML with innerHTML. Every value from outside goes through applyParams(), whether it comes from the URL or from localStorage (fc-tricalc-v4). Units must match a fixed list, the preset must be a known key (findPreset), the start time must match ^\d{2}:\d{2}$, and every distance and pace is converted with num(). So only built-in labels and numbers reach markup.

02Code quality

11 inline event handlers replaced by one listener
Fixed

The onclick/onchange attributes, including the two built in script strings for preset buttons, are now data-action attributes handled by a single ACTIONS table and one delegated click listener. The race dropdown has its own change listener. This is what lets the CSP leave out 'unsafe-inline' for scripts.

Check: the old suite check, "every inline handler is defined", would now pass with nothing to check, so it was replaced by real clicks on the units, Apply, other-distance, Reset and dropdown controls. In Chromium, Share and Copy were also clicked (toast shown, clipboard filled), as were Now and Get Coached.
The look matches the old page
Confirmed

Screenshots were taken before and after at 1280 px and 390 px. Since the container can't reach the Tailwind CDN, the "before" run served the CDN script from a stand-in that injects CSS compiled from the original page, and Font Awesome from npm. The two match apart from icon anti-aliasing and the number font: JetBrains Mono became the system monospace font. There's no sideways scroll at either width. Caveat: this container has Inter installed as a system font, so the "after" text still looks like Inter there. On real devices it will be the system font listed above.

Editing the script means updating its hash
Open (by design)

That's the cost of hash-based CSP: change one character in the script and browsers refuse to run it. A comment above the CSP says so and gives a one-line node -e command that prints the new hash. The suite fails if the two drift apart. A first draft of that comment contained the literal text <script>, so the regex-based hash finder matched the comment instead of the script. The suite caught it, and the comment and command now avoid the literal tag. The "Get Coached" button also still has no destination (it scrolls to the top) until a booking URL is supplied.

Update 2026-11-20: "Get Coached" now links to https://fullcirclecoaching.com/contact/. See review 95. The hash point above still stands.
New suite checks, each proven against a broken copy
Fixed

New checks: nothing in src/href points off the page, no @import or remote url(), no inline handlers, exactly one inline script, default-src 'none', no 'unsafe-inline' for scripts, the hash matches, every data-action has a handler, and every icon has a symbol. Seven broken copies were run, and each failed the right check: a CDN script added back, a protocol-relative font link, a script edited without updating its hash, a preset action emptied, an onclick added back, a missing icon symbol, and default-src 'self'.

jsdom's CSS parser can't read the compiled Tailwind CSS and reports "Could not parse CSS stylesheet". Only that exact message is ignored, in this suite alone. Script errors still fail, and real Chromium logged none.

Reports 90, 91 and 92 rendered as blank pages
Fixed

All three stopped their CSS at footer { with no closing </style>, so the browser read the whole report as CSS. Headless Chromium showed 0 characters of visible text for each. The missing footer rule and </style> were restored from 89.html. They now show 2,448, 2,722 and 1,989 characters. No other report is missing </style>.
