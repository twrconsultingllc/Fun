01Security

The change is layout/CSS only — head block, script/form/external-resource posture unchanged
Confirmed clean
Re-checked from scratch rather than assuming the earlier 07.html findings still hold: the CSP, referrer, viewport, and description meta tags are byte-for-byte unchanged, and there are still zero <script> tags, zero on*="…" handlers, no http:///https:// reference anywhere in the file, no @import, and no <form>.
No nested interactive content from wrapping each card in a single <a>
Confirmed clean
Making a whole box clickable by wrapping it in an <a> is the one way this kind of change commonly breaks HTML: if the box still contains its own inner <a>, browsers auto-close the outer anchor at the first nested one and the two links silently fight over the same click. Checked directly: each card's heading, description, and status/arrow spans are plain <h2>/<p>/<span> elements with no anchor inside — a script count confirms exactly one <a> per card block, the card itself. The old markup had the opposite risk profile (the anchor buried inside the heading), which is exactly the pattern this change removed.
All four link targets are unchanged and still resolve
Confirmed clean
The four href values (usecase.html, plan.html, build-plan.html, ui-plan.html) moved from each card's <h2> onto the card's own <a> wrapper without changing, and all four still resolve to real files in the same directory.

02Code quality & accessibility

Keyboard and screen-reader behavior improved, not just mouse hover
Confirmed clean
A whole-card link is only a real accessibility win if it also works without a mouse. The new CSS pairs every :hover rule with a matching :focus-visible rule (border highlight, lift, and the arrow's shift), and adds an explicit outline on :focus-visible so keyboard users see exactly the same affordance sighted mouse users get — the earlier version only styled the small nested title link's hover state, with no visible focus ring of its own. Screen readers now announce each card as one link with its full heading-plus-description text as the accessible name, rather than a static box containing an unrelated short link.
The decorative arrow is correctly hidden from assistive tech
Confirmed clean
Each card's new → affordance is marked aria-hidden="true", so it doesn't get read aloud or duplicated into the link's accessible name — it's a purely visual cue for sighted users, and the heading and description text already carry the actual meaning.
Contrast re-checked for the heading text's new color, and for the hover/focus box-shadow in both color schemes
Confirmed clean

The card heading now renders in --link instead of the previous default --text, since the whole card being a link is signaled partly by tinting its title the same color as any other link on the page. This exact pairing (--link/--accent on --panel) was already computed clean in 07.html at 8.61:1 (dark) and 5.76:1 (light) for the arrow; it applies unchanged to the heading, which uses the same two hex values. The hover/focus box-shadow: rgba(0,0,0,0.18) is a pure decorative shadow, not a text/background contrast pair, so it isn't a WCAG contrast concern in either color scheme — it reads as a visible but subtle lift in both dark and light mode since it's layered under the panel's own background rather than replacing it.
