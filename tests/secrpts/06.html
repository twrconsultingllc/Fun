01Security

CSP, referrer, description, and viewport meta tags present and correctly scoped
Confirmed clean
ui-plan.html uses the exact same head block as plan.html and build-plan.html: script-src 'self' with no 'unsafe-inline', style-src 'self' 'unsafe-inline' for its inline style="…" width attributes, referrer set to strict-origin-when-cross-origin, and its own page-specific description. This is deliberate: even though this page's whole subject is a future UI that would need a looser, 'unsafe-inline' CSP to actually run, this page itself has zero JavaScript, so it correctly keeps the stricter policy its two siblings use rather than adopting the future page's CSP prematurely.
No external resources, scripts, forms, inline handlers, or secrets
Confirmed clean
Grepped the file directly: zero <script> tags, zero on*="…" handlers, no eval(/fetch(/XMLHttpRequest, no <form>, no external href="http…" or src="http…", no @import, and no API key/.env reference. Every link is a same-origin, same-directory relative reference (plan.html, build-plan.html, and their anchors, plus this page's own #section anchors) — no target/rel hardening needed, same reasoning 05.html already established for build-plan.html.
The page's mockup buttons and textarea are genuinely inert, not fake-interactive
Confirmed clean
This page's central risk, given its subject matter, is describing a future interactive page while accidentally shipping something that looks interactive today. Checked directly: the mockup's <button> elements carry a real disabled attribute (not just a CSS style making them look inert while remaining clickable), and its <textarea> carries a real disabled attribute too — both are genuinely non-interactive at the HTML level, not simulated via CSS or JS. The page's own .callout.warning disclaimer directly above the mockup states this plainly before a reader reaches it. The mockup's three <details> elements are the one exception worth naming explicitly rather than leaving implicit: their open/close toggle is genuinely live, because that's native, JS-free HTML behavior every browser provides — it isn't something the future build would need to add, so it doesn't contradict the "not functional" framing.

02Code quality & accessibility

Five unused CSS rules carried over from copying build-plan.html's stylesheet
Fixed
ui-plan.html's stylesheet started as a copy of build-plan.html's, with page-specific mockup rules added on top. Checking which selectors the copied stylesheet actually matches against the markup turned up five that don't: h3 (this page only uses h1, h2, and its own new h4), caption (no <caption> element anywhere), .session-meta and .session-meta strong (a per-session metadata row that build-plan.html needs and this page doesn't), and .badge.done/.badge.in-progress (this page only ever shows the base, neutral .badge — a "Not started" marker — since it deliberately doesn't track its own status the way build-plan.html does).
Fixed: removed all five. The base .badge rule, and the generic table/th/td selectors, were left alone — both are actually used on this page.
Contrast computed for the new color pairings this page introduces, not assumed from the inherited palette
Confirmed clean

This page reuses build-plan.html's already-verified palette, but it puts that palette into two combinations neither sibling page has: plain paragraph text (not just short inline <code> snippets) sitting on a --code-bg background inside the mockup's <details> containers, and a disabled-button treatment (--text-dim text on a --panel-border background) that doesn't exist anywhere else in this repo. Computed WCAG relative-luminance contrast directly for each:

PairDark modeLight mode
--text on --code-bg (mockup details body text)15.70:113.16:1
--text-dim on --code-bg (checklist "pending" marker)8.24:15.54:1
--good on --code-bg (checklist "done" marker)9.59:15.01:1
--text-dim on --panel-border (disabled button)5.94:14.87:1

Every pair clears the 4.5:1 WCAG AA threshold for normal text in both modes. The tightest margins are both in light mode — --good on --code-bg at 5.01:1 and the disabled button at 4.87:1 — worth knowing if either color is ever darkened further, but both pass with real margin today.
