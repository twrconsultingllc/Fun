Review #24 — haunted-house.html (new page)

A new single-file game: Haunted House Explorer. You search six rooms for five hidden items and escape through the front door, at a scare level from 1 (friendly, little kids) to 5 (horror, adults only, behind an age gate). Levels 4 and 5 add a hunter you must hide from. The page is linked from index.html as a new section, and a new haunted-house test suite covers it.

01Security

CSP and referrer meta tags present, no outside origins
Confirmed clean
The page carries the repo's standard policy with nothing widened: default-src 'self', img-src 'self' (no data:, since there are no images), object-src 'none', base-uri 'none', form-action 'self', plus referrer set to strict-origin-when-cross-origin and a description. A grep for (src|href)="https?:, @import and off-origin url( finds nothing. All art is inline SVG and emoji, and all sound is synthesised with Web Audio, so there's nothing to fetch. 'unsafe-inline' stays in script-src for the same reason as every other single-file page: the script is inline by design.
No user-controlled data reaches the DOM as markup
Fixed
The game takes no text input and reads no URL, storage or network data. All game text goes in through textContent. Grep shows 2 innerHTML writes left, and both take constant strings from the script itself: ART[roomId] + DRESSING[state.level] (the room is validated against ROOMS first, and the level against LEVELS) and the two fixed scare SVGs.
Fixed: a third write, $('hud-level').innerHTML = '', was changed to textContent = '' so no innerHTML use is left that isn't constant art.
No network, storage, eval or inline handlers
Confirmed clean
A grep for fetch(, XMLHttpRequest, WebSocket, localStorage, sessionStorage, indexedDB, eval(, new Function, document.write and on*=" attributes finds nothing. The suite asserts the last two. Saving nothing is deliberate: the chosen level is never remembered, so the page can't reopen on level 5 for a child after an adult played.
Test hook exposes only game state
Confirmed clean
window.__haunted follows the __snake/__swarm pattern. It exposes the level and room tables and the game's own functions, and nothing on the page reads it. A player could use it from DevTools to see where items hide. That's cheating at a toy, not a security issue. Its start(5) refuses to run unless level 5 was already confirmed through the age gate, and the suite asserts that.
Clickjacking (frame-ancestors) not enforceable
Open
Same as every GitHub Pages page in the repo: frame-ancestors is ignored in a meta CSP, and Pages can't send response headers. It's architecturally blocked, and the risk is low because the page has no privileged actions to trick anyone into.

02Content & code quality

Scare levels are separated by construction, and tested
Confirmed clean
The page always opens on level 1. Level 5 needs an explicit "I'm 18+" in a modal whose focus starts on "No, go back", and Cancel and Escape both leave the previous level selected. The age check is self-declared, like any game rating prompt: it keeps a child from wandering in, it isn't verification. The suite pins the content separation:
  • Hotspot text uses 4 tiers (level 1, level 2, level 3, levels 4-5), and the tiers never get milder as the level rises.
  • Every text levels 1-2 can show (room descriptions, hotspot text, surprises, intro, ending) is checked against a list of horror words (blood, dead, kill, scream, teeth, hair and others), with 0 matches.
  • Levels 1-2 have no hunter, and levels 1-3 never use the full-screen face. Level 3's scare is the cartoon "BOO!" ghost.
Photosensitivity: flicker stays under 3 flashes per second, and reduced motion turns it off
Confirmed clean
The level 4-5 light flicker is 2 dims in 1.2 s, under WCAG 2.3.1's three-flashes-per-second threshold. It dims toward dark and never flashes bright. The full-screen face is a single appearance followed by a small shake, not a repeated flash. In headless Chromium with reducedMotion: 'reduce', the computed animation-name for both the scare and the flicker is none. The level 5 gate and the title-screen note both warn about the flicker.
Text contrast (WCAG AA), computed
Fixed
Relative-luminance ratios were computed for each level's palette. Dim text on the page ranges from 6.08 to 11.68, message text on its panel from 14.20 to 19.51, and hotspot labels over the lightest wall (level 1) 5.96. Toast text is 15.93 and the age-gate text 16.77.
Fixed: level 5's red accent #c9453a measured 4.32:1 on the page, which fails AA for the normal-size italic whisper line. It became #e0564a: 5.50:1 on the page, and 5.08:1 for the dark button text drawn on it.
Keyboard and screen-reader access
Fixed
Every hotspot, exit and control is a real <button> with an accessible name, and searched spots say "(searched)". Game messages are in aria-live regions, and scares are also described in text. The flashlight follows keyboard focus as well as the pointer, so the dark levels work without a mouse.
Fixed: the age gate's focus trap let Shift+Tab from the first button escape the dialog. Tab and Shift+Tab now both swap between its two buttons.
Layout at common sizes
Fixed
Screenshots were taken in headless Chromium at 1100×900 (every level, the hunt, the face scare) and 390×844 (phone), with 0 console errors. Hotspot labels hide under 560 px so they don't overlap, and every tap target is at least 48 px.
Fixed: at 1100×900 the room-exit buttons fell below the fold. The scene's height cap went from 64vh to 54vh.
Loudness of the level 4-5 screams not judged by ear
Open
The audio code runs without errors in Chromium, where Web Audio exists, and as a silent no-op in jsdom, where it doesn't. Nothing plays until the player presses "Enter the house". The scream's gain is capped, and there's a mute toggle on both screens. Nobody has listened to it, though, so the actual loudness on real speakers needs a human check on the live site.
