01Security

Strictest CSP of any toy page so far
Confirmed clean

All three pages carry script-src 'self' with no 'unsafe-inline' for scripts or styles, frame-src https://www.youtube-nocookie.com only, connect-src 'none', form-action 'none', object-src 'none', base-uri 'none'. That was possible because the JS lives in two same-origin files instead of inline, and every dynamic style is set through the CSSOM (el.style.cssText), which CSP does not block, rather than a style="…" attribute, which it does.

Verified in a real headless Chromium (Playwright): no CSP-violation console messages on any of the three pages, including after embedding a video. The suite also pins it: academy.dom.test.mjs asserts the script-src/frame-src values and greps each file for inline <script> bodies, on*= handlers and style=" attributes.

A pasted YouTube link cannot inject markup or point the frame elsewhere
Confirmed clean

parseYouTube() only returns an 11-character [A-Za-z0-9_-] ID, and only when the host is exactly youtube.com, youtu.be or youtube-nocookie.com (with an optional www./m./music. prefix). The iframe is built with createElement and its src is always the fixed prefix https://www.youtube-nocookie.com/embed/ + that ID, so there is no path from input to markup. 11 accepted shapes and 8 rejects are tested, including the look-alike host youtube.com.evil.example, a javascript: URL and an ID with "><img> appended.

Stored values are re-validated on read
Confirmed clean
A pasted ID is saved to localStorage (fca:vid:*) so it survives reloads. On read it's checked against the same ID regex again, so a hand-edited or tampered value (tested with x"><script>) renders the empty slot, not a frame. Every storage call is wrapped in try/catch for private-mode and blocked-storage browsers.
Query-string routing renders untrusted values as text only
Confirmed clean
?c= is matched against the course list; an unknown value shows a "not found" notice that echoes it through textContent (tested with ?c=<img src=x>: zero <img> elements created). ?l= is parseInt'd and range-checked, falling back to lesson 1. The only innerHTML writes are static SVG strings in courses.js and the play icon (grepped: 2 sites, neither takes input).
Referrer policy lets YouTube embeds play
Confirmed clean
The page meta and the iframe both use strict-origin-when-cross-origin. YouTube rejects embeds that send no referrer at all (its "Error 153"), so this is the tightest policy that still works; it sends only the origin https://twrconsultingllc.github.io, never the path or query string.
YouTube iframe is not sandboxed
Open
A sandbox attribute is extra hardening. It isn't strictly needed: the frame is cross-origin, so it already can't touch the page, and frame-src pins it to one host. Adding it is an easy way to break playback, though, and this sandbox can't reach YouTube to check it (the frame renders black here for network reasons, not because of CSP). Left off until someone confirms on the live site that playback still works with sandbox="allow-scripts allow-same-origin allow-presentation allow-popups".
Google Fonts loads without SRI
Open
Same situation as tricalc.html: the Fonts CSS is generated per browser, so it can't carry an integrity hash. It's a stylesheet (with the CSP, it can't run script) and the font stack falls back to system fonts if it fails. Architecturally blocked short of self-hosting Inter.
No secrets, emails or personal data in the new files
Confirmed clean
The email-pattern grep over academy/ and the new test found no hits. Commit identity is Claude <noreply@anthropic.com>, one of the two allowed identities. All course content is generic coaching copy, and every placeholder youtube ID is empty.

Multi-file rather than single-file
Confirmed clean
CLAUDE.md prefers single-file pages "unless there is a concrete reason". Here there are two. Three pages share one content model, so lessons and video IDs are edited in one place (courses.js). And external same-origin scripts are what make the no-unsafe-inline CSP possible. The folder is self-contained, and nothing outside it depends on it except the one landing link.
