Review #36 — jarvis.html

A new page, J.A.R.V.I.S. Demo: an animated orb, a clock, and a chat with a small built-in "brain" that answers the time and date, jokes, fun facts, simple math, coin flips, dice and a launch countdown. It speaks its answers and can listen through the browser's speech recognition. The page was supplied by the user and is linked from index.html as section-25.

01Security & privacy

No CSP, referrer policy or description
Fixed

The page as supplied had none of the meta tags the rest of the site carries. It now has referrer strict-origin-when-cross-origin, a description, and a CSP that allows only its own inline script, styles from itself and fonts.googleapis.com, fonts from fonts.gstatic.com, and images from itself or data: (the favicon). connect-src 'none' means the page can't send anything anywhere, which backs up its "no internet brain" claim. form-action 'none', object-src 'none' and base-uri 'none' are set. No external scripts. The Chromium render loaded Chakra Petch under this policy with no CSP errors.

Fix: added the head block, plus a favicon so the browser doesn't ask for /favicon.ico.
Typed and spoken text is shown as text
Confirmed clean

Every chat bubble is built with createElement and textContent. A grep for innerHTML, insertAdjacentHTML, document.write and eval finds nothing. The suite sends <img src=x onerror=alert(1)> and checks it appears as text and no element is created. The stored name can only be letters ([a-z]+, capitalised).

Only a first name is stored, on this device
Confirmed clean

The one thing saved is jarvis-name in localStorage, and the page says "I'll remember that on this device". Reads and writes are wrapped in try, so private browsing doesn't break the page.

The mic isn't offline in Chrome
Open

The answers are worked out in the page, but Chrome's and Edge's speech recognition send the recorded audio to the browser maker's speech service. So "no internet brain" is true of Jarvis, not of the mic. The CSP can't block this, because the browser makes that request, not the page. Typing stays fully on the device. Left open because it's the user's own wording and a question of how to describe it, not a code bug. A one-line note by the mic would close it.

02Code quality & accessibility

"What is seven times eight" answered with the time
Fixed

The help text suggests asking "seven times eight", but the time rule /what.*time/ matched "times" and ran first, so Jarvis said "It's 7:00 PM." Seen in the first Chromium run. The rule is now /what.*\btime\b/. The suite checks both that question and "what time is it".

Fix: word boundary on "time".
Math words matched inside other words
Fixed

x, over and add were replaced anywhere, so "next", "however" and "address" turned into operators. They now need word boundaries. Tested: "12 x 3" is 36, "next 4 boxes 5" and "however 4 5" aren't math.

Fix: \b…\b around each operator word.
"I'm fine" became the user's name
Partial

"I am …" and "I'm …" set the name, so "I'm fine" made Jarvis call the user Fine from then on, saved. Common words after "I'm" (fine, good, hungry, tired, sorry, and about 60 more) are now ignored, and "my name is" and "call me" always work. Partial because it's a word list: "I'm starving" would still be taken as a name. Dropping "I'm" as a name trigger would close it fully, at the cost of "I'm Tony" no longer working.

Fix: a list of words that aren't names.
Could get stuck on PROCESSING
Fixed

The orb went back to STANDBY only when speech ended. If speech failed or never started (no voices installed, which is the case in headless Chromium), it stayed on PROCESSING. An onerror handler and a 1.5 s fallback now return it to STANDBY. Checked in Chromium and in the suite.

Fix: onerror plus a timeout.
Header text contrast
Fixed

The small header text used #1b7a45: 3.73:1 on #020a06 and 3.45:1 on #06170e, below 4.5:1. It now uses a new --label colour, #2fa862: 6.58:1 and 6.07:1. The input placeholder uses the same colour. #1b7a45 stays for borders, where 3:1 is the bar. Main text is 17.99:1 and the bright green 15.10:1.

Fix: --label for header and placeholder text.
Crashed without a canvas
Fixed

With no 2D canvas (jsdom) the orb loop threw, and a missing matchMedia stopped the whole script, so the chat never started. The orb is now skipped when there's no canvas, and matchMedia is checked first. Real browsers are unaffected.

Fix: two guards.
Linked both ways, renders at desktop and phone width
Confirmed clean

index.html gets section-25, added to the centring rule, and the page has a "← Fun" link back. The index suite checks the link, that the file exists and that the section is centred. Headless Chromium at 1280×800 and 390×844: no page errors, no sideways scroll, and the orb, chat and input all fit.

Reduced motion still pulses
Open

With "reduce motion" on, the rings stop turning but the glow and ring sizes still pulse. The pulse is slow and small in STANDBY and faster while speaking. Left open as minor. Holding the pulse steady when reduce is set would close it.
