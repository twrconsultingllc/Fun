Review #26 — daily-wire.html (new page and feed workflow)

A new personal news reader, My Daily Wire. It shows headlines from 35 free public feeds as magazine cards, grouped into 8 categories: News, Tech, Dev & AI, Science & space, Security, Live data, Fun and Business. It has category chips, search, Unread only, and read state kept in the visitor's own browser. Because browsers block cross-site feed requests, the page reads one same-origin file, daily-wire/feeds.json. A new GitHub Actions workflow runs daily-wire/fetch-feeds.mjs every 6 hours to rebuild that file, committing only when the headlines change. This is the repo's first workflow and its first code that runs on a schedule, so it gets the same review as the page.

01Security

CSP and referrer meta tags, with a named image-host list
Confirmed clean
The page keeps the repo's standard policy except for img-src, which lists 17 publisher image hosts by name. There's no https:, data: or * source; *.ytimg.com is the only wildcard, and it covers YouTube's thumbnail servers. connect-src 'self' means the page can only read its own daily-wire/feeds.json. The referrer policy is no-referrer, which is stricter than the repo default, so publishers don't learn which page their pictures or links were opened from. Every image also carries referrerpolicy="no-referrer", and every story link carries rel="noopener noreferrer". No fonts, scripts or stylesheets load from anywhere else. The wire-dom suite checks the host list is identical in feeds.config.json, the page script and the CSP, because a host missing from any one of them breaks pictures without any error.
No markup injection path, and the page trusts nothing in feeds.json
Confirmed clean
A grep for innerHTML, outerHTML, insertAdjacentHTML, document.write and on*=" attributes finds 0 uses. Every feed string reaches the DOM through textContent. The fetcher already reduces titles and summaries to plain text, but the page checks everything again:
  • Links must parse as http(s) with no credentials.
  • Images must be https on a listed host.
  • Ids must be 12 hex characters, and categories must be known.
  • Strings are length-capped.
The suite feeds it javascript: and data: links, an <img onerror> title, a <b onmouseover> summary, a tracking-pixel host, an http: image, bad ids, unknown categories and a duplicate id. The bad entries are dropped, the HTML shows as literal text, and a window.__pwned flag the payloads would set stays unset. Read state in localStorage is filtered to well-formed ids, and tampered or corrupt values are ignored without errors.
Feed parsing is hardened against hostile XML
Confirmed clean
fetch-feeds.mjs parses with fast-xml-parser 5.11.1 and processEntities: false, so a DOCTYPE can't declare entities that expand. A three-level entity bomb in fixtures/daily-wire/hostile.xml stays as the literal text &c;. External entities (XXE) make the parser throw, xxe.xml is refused, and the failed feed just keeps its previous items.
  • <script>, <style>, <iframe> and comments are removed with their contents, then every tag is stripped.
  • Invalid numeric entities and control or zero-width characters are dropped.
  • Future dates are clamped to now.
  • Look-alike hosts such as imgs.xkcd.com.evil.example are rejected.
The 5 MB response cap, the 20-second timeout and the "must end on https after redirects" rule are in the code but aren't exercised by a test, because the suite runs with no network.
Double-escaped markup could survive the fetcher's tag stripping (CodeQL)
Fixed
CodeQL flagged toPlainText() on the PR with "incomplete multi-character sanitization", and the flag was right. It stripped tags once and then decoded entities again, so a feed title written as &amp;lt;script&amp;gt; came out as the literal text <script>. The page only ever sets it with textContent, so nothing could run, but the fetcher promises plain text and didn't deliver it.
Fixed: a new stripMarkup() decodes and strips repeatedly until the text stops changing (at most 5 passes), then drops any < or > that's left, so no output can contain a tag. The tag pattern now needs a letter, /, ! or ? after the <, like real HTML. Without that, "3 < 5 > 2" lost its "5". New tests cover double- and triple-escaped tags, a split-up <scr<script>ipt>, and plain comparison text. CodeQL's two other alerts were substring URL checks in the test file. They weren't exploitable, but they're now exact comparisons, so the pattern isn't in the repo.
Workflow token was on disk while third-party code ran
Fixed
actions/checkout leaves the job's write token in git's config by default. That meant the fetcher, and fast-xml-parser's code inside it, ran with a token that could push to the repo.
Fixed: checkout now uses persist-credentials: false. Only the final commit step receives GITHUB_TOKEN, and it only uses it to push daily-wire/feeds.json. The job's permissions are just contents: write, with a 10-minute timeout and a concurrency group so two runs can't race.
Supply chain for the fetcher
Confirmed clean
Both actions are pinned to full commit SHAs, resolved with git ls-remote on 2026-09-26: actions/checkout v7.0.1 is 3d3c42e5… and actions/setup-node v7.0.0 is 82076278…. The install is npm ci --ignore-scripts from the committed lockfile. It pulls 8 packages, every one MIT-licensed, resolved from registry.npmjs.org with an integrity hash, and none with an install script. npm audit reports 0 vulnerabilities. node_modules/ is already covered by the root .gitignore.
Publisher images tell those sites who is visiting
Open
It's the trade-off chosen with the magazine layout, and it was explained before the user picked it. When a card shows a picture, the publisher's image server sees the visitor's IP address and when the picture loaded. no-referrer hides which page they came from, and the allowlist stops arbitrary trackers. A picture can't run code or read the page. The fully private option, copying thumbnails into the repo, was turned down because it would grow git history by megabytes every run.
Clickjacking (frame-ancestors) not enforceable
Open
Same as every GitHub Pages page: frame-ancestors is ignored in a meta CSP, and Pages can't send headers. It's architecturally blocked, and the risk is low because the page has no privileged action to trick anyone into.
Identity and secrets in the new files; bot commit identity recorded
Confirmed clean
An email-pattern grep of every new and changed file finds only the three already-allowed no-reply addresses and two fake .example addresses inside test inputs. A secret-pattern grep finds nothing. The workflow commits as github-actions[bot] <41898282+github-actions[bot]@users.noreply.github.com>, which is GitHub's no-reply address for the bot. CLAUDE.md's Full Monty identity list now names it, so hourly-style bot commits don't read as a finding later. The fixtures and sample data use only made-up headlines and .example domains.

02Correctness

Undated items vanished from feeds
Fixed
Only the newest 2 items per feed were kept regardless of age. Everything else had to be dated within 21 days, so undated items (possible in RSS) were dropped silently. The hostile fixture lost 2 valid items this way.
Fixed: items with no date are kept, sorted last, because their age can't be judged. The suite checks the 4 valid hostile items all survive, and that an old release feed is trimmed to its 2 always-kept items.
"30 seconds ago" showed as "1 min ago"
Fixed
The relative-time helper rounded minutes, so 30 s became 1. The test's expected value, "just now" for anything under a minute, was worked out from what the label means, not copied from the page.
Fixed: minutes are now floored. Hours and days still round, so 90 min still shows "2 h ago", and the suite pins 7 boundary cases.
Lazy loading not guaranteed
Fixed
Images set img.loading = 'lazy' as a property. jsdom doesn't reflect it, and the suite caught the missing attribute.
Fixed: loading and decoding are set with setAttribute, which works everywhere, so the first view doesn't pull every picture at once.
"Could not be loaded" flashed on every visit
Fixed
The first render ran before fetch() returned, so every visit briefly showed the failure notice.
Fixed: a loading state shows "Loading headlines…" until the data arrives or the fetch fails.
Paywall pill was hard-coded to one feed id
Fixed
The page added nyt to its paywall set by name, so the config's paywall flag did nothing for any other feed.
Fixed: the fetcher copies paywall: true into each feed's status in feeds.json, and the page reads it from there. Both halves are tested.
Feed URLs and image hosts not yet confirmed live
Open
This container's network policy blocks every feed host (CONNECT 403), and WebFetch was refused as well. Only the two GitHub release feeds were confirmed; they carry avatar thumbnails from avatars.githubusercontent.com, which the config deliberately doesn't show. The four YouTube channel ids were confirmed against their channel pages by web search. Everything else, including the other 16 image hosts, comes from knowledge of each publisher's feed and is unverified. The first real run settles it. Each feed's success or error shows in the page footer and the workflow log, and any image host that had to be dropped is listed in feeds.json → imageHostsDropped.

03Accessibility & layout

Dimmed "read" text failed contrast
Fixed
Computed WCAG ratios: read titles and summaries were 3.12:1 on the light card and 3.84:1 on the dark one. That's below 4.5:1, and 18 px semibold isn't large text under WCAG.
Fixed: the read color is now #697183 (4.89:1) in light and #858d9e (5.18:1) in dark. It's still clearly dimmer than unread text, which is 17.62:1 and 14.44:1. Other computed ratios, light/dark: summary text 6.23/7.22; category labels 5.18/7.50 at worst (Fun, News); a no-picture card's large source name 4.21/5.90 at worst, which passes the 3:1 large-text rule; chip counts 4.93/6.18; the masthead accent 4.59/7.42.
Keyboard, labels and phone layout
Confirmed clean
Category chips are real buttons with aria-pressed, and so are Unread only and Mark shown as read. The search box has a label, and / jumps to it. Each card's headline link covers the whole card, and a focus ring appears only for keyboard focus. The shown count is announced through an aria-live region. Headless Chromium screenshots at 1280 px (light and dark) and 390 px showed no console errors and no horizontal scroll. The grid dropped to one column on the phone.
