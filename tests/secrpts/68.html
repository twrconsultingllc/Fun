You found learned phrases too pushy. Every miss asked "What were you trying to say?", and whatever you said next was saved as the meaning, even a new question. 01Security and privacy

Phrases are no longer saved without being asked
Fixed

Before, a miss quietly set pendingTeach, so your next sentence was written to the database as what the phrase meant, whatever it was. That was a write to storage that nobody asked for.

Fix: A miss now only remembers the phrase in memory (lastMiss), for the very next turn. Nothing is saved unless you say learn that and then answer, or say when I say X, I mean Y. A "no" to "Did you mean …?" no longer starts teaching either. lastMiss is cleared at the start of every turn, so "learn that" can only ever teach the phrase from the turn just before.
Every save still goes through the same checks
Confirmed clean

Both ways of teaching end in one new function, taught(), which holds the code the old flow had: personal() on both the phrase and its meaning (refused, with the reason), short-term memory never saved as a phrase, and then learn(), which checks personal() again and saves through store(). The suite's checks still pass: no localStorage write anywhere in the page, and exactly one 'readwrite' transaction. The phone-number refusal and "my cat is Tom" checks pass when taught through "learn that".

The new link does only what it says
Confirmed clean

The miss answer now carries a second link, ⟦learn that⟧, from a fixed constant (LEARN_IT) that was added to CHIP_CMDS. Nothing typed becomes a link (that check passes unchanged). Tapping it saves nothing: it only asks "What did you mean by …?". "Learn that" was added to the teach capability and to the Soul stone of the gauntlet, so the checks "every command link belongs to a capability" and "every link command is understood" cover it.

Phrases are matched with regular expressions, not built from text
Confirmed clean

WHEN_I_SAY and LEARN_THAT are fixed patterns run against the normalised phrase, which has only letters, digits, spaces and apostrophes. No pattern is built from what you type. WHEN_I_SAY's lazy (.+?) is followed by a fixed set of words and anchored at both ends, so there is no nested quantifier to slow it down. The old __proto__ check still passes through "learn that".

CSP and markup unchanged
Confirmed clean

No new host, element, style or script. The CSP meta tag is unchanged (the suite pins it).

02Code quality

With the full brain on, "Did you mean …?" came before it
Fixed

In answerCore(), the meaning module was asked before the full brain. Any match between 0.60 and 0.80 asked "Did you mean …?" about something the full brain could simply have answered.

Fix: With the full brain running, the meaning module acts only when it's sure (the same sure test as before: at least 0.80, a clear gap to the next match, and never a command that asks first). An unsure match goes to the full brain. If the full brain doesn't answer (for example, the question is over 400 characters), the old "Did you mean …?" comes back. Without the full brain, nothing changes. Sure matches, patterns, the knowledge pack and protocols all still come first; the suite's 89 pinned phrasings still answer exactly as they do without the full brain.
Spoken phrasing without a comma
Fixed

A phone sends "when i say lights please i mean make the orb blue" with no punctuation. The first draft of WHEN_I_SAY also split at "please", so the suite's check found "lights" taught to mean "i mean make the orb blue".

Fix: "Please" was taken out of the split words. It now splits only at "I mean", "I meant", "it means", "that means", "I want you to" and "you should". The spoken phrasing is pinned next to the typed one, as CLAUDE.md asks.
The words that describe teaching
Fixed

The Soul stone's note, the teach capability's hint, "what have you learned" with nothing learned, the miss answer's "why?", and the code comment all said "tell me what you meant". They now describe "learn that" and "when I say X, I mean Y". This page has no separate user guide. The build plan's Interim section has a dated follow-up note.

The suite
Confirmed clean

jarvis-test (jsdom): 1786 checks, all passing. The "Learned phrases" section was rewritten for the new flow: a miss offers "learn that" and teaches nothing, "learn that" a turn later has nothing to learn, "nothing" leaves it, "when I say …" typed and spoken, and a meaning it doesn't know isn't learned. The meaning module's "no" now offers "learn that" instead of teaching, and the full brain section checks that a sure match runs first while an unsure one goes to the full brain. Eleven older checks that taught the old way (miss, then "I meant …") now say "learn that" in between. Their expected answers weren't changed. Only the full brain check's phrase changed, from "tickle my funny bone" to "make me chuckle", because "funny" is already understood by a pattern and never reached the meaning module.
