Review #61 — J.A.R.V.I.S. Session 10: protocols and follow-ups

The test copy can now save protocols: one phrase that runs up to six of its own commands in turn. A protocol is kept as a name checked by personal() and a list of fixed command IDs, in a new protocols table that version 2 of the database adds. Two are built in, House Party and "wake up, daddy's home". A HUD line shows a run's progress. Follow-ups (again, go back, bigger, smaller, faster, slower, what was that, yes, no, why, and fragments like "now Jupiter") use a context kept in memory only.

01Security and privacy

Head block and CSP unchanged
Confirmed clean

git diff of jarvis-test.html touches no <meta> line except the description, which now mentions protocols and follow-ups. The CSP, referrer policy and charset are what they were. Nothing new is fetched: protocols and follow-ups are plain script, and IndexedDB isn't governed by the CSP. personal() and its patterns have no changed line.

One place that saves, still
Confirmed clean

The suite's Session 9 checks pass unchanged: no localStorage write anywhere, exactly one 'readwrite' transaction, in flush(), only save() queues a write, and save() calls fits() on every record. Protocols get a new case in fits(), and the page saves them in exactly one place (finishProtocol) and removes them in two (delete by name, the scrub), which the suite pins by counting save('protocols', calls.

A protocol holds a checked name and fixed command IDs, nothing else
Confirmed clean

A record is exactly {steps:[…]}. fits() refuses words as a step, an extra field, a seventh step, two scenes, a name that isn't in its saved form, a personal name, the built-in-only sys:boot, and a 21st name. The 82 step IDs are fixed kind:name codes that pass personal(), and every ID's own command text parses back to the same ID through the page's own parsers. After the suite made protocols from thirteen sentences, the database held only names and IDs: none of the sentences' words (for example make the orb, tell me a joke, sparkly, a phone number) was in it. In Chromium, a protocol read back from real IndexedDB after a reload was {"steps":["orb:purple","speed:slow","scene:galaxy"]}.

The name goes through personal(), as said
Confirmed clean

The name is checked twice: as you said it, so "my mom" isn't saved as "mom" once "my" is trimmed, and in its saved form inside fits(). A phone number and "my mom" were refused in the suite, with the reason given by "why?". A name is at most four words and 30 characters, and can't be a built-in name.

Nothing destructive, no camera, mic, places or your words in a protocol
Confirmed clean

A part that starts with forget, delete, erase, clear, wipe, reset, remove or unlearn, or means "reset my settings", is refused. So are the threat scan and hand control (the camera only starts when you ask), always listening, a reboot, places on the globe (a saved place could give away where you live), "write …" (it would save your words), the opening-scene setting, and a protocol inside another. None of these has a step ID, so fits() refuses them too even if the parser were wrong. Each refusal is pinned in the suite.

Follow-up context is memory only
Confirmed clean

The context is one object, talk: last command, its frame, the scenes opened this visit, the last answer, the reason, a pending question. No call to save() or store() takes any of it, the database has no table for it, and after a run of follow-ups neither the jsdom database nor the real IndexedDB in Chromium contained any of the commands or answers. A reload starts it empty (pinned: {"lastCmd":null,…,"scenes":[]} and "again" says there's nothing to repeat), while the protocols are kept.

Delete one by name; still no wipe
Confirmed clean

"Delete movie night" asks for a yes first and removes only that record. "Delete all my protocols", "forget every protocol" and the like are refused with the reason (your decision that there are no wipe commands). Built-ins can't be deleted. The memory core's protocol star deletes that one protocol, like every other star. No clear() or deleteDatabase() was added (the suite's existing check).

Runs are counted by a fixed ID, never by name
Confirmed clean

Three IDs were added to EVENT_IDS: cmd:protocol for any protocol you made, and cmd:house-party and cmd:wake-up for the built-ins. The suite checks one run adds one cmd:protocol and that no event ID or saved count contains a protocol's name. Each step still counts as its own command, as it would if you'd said it.

Your words can't become a command link
Fixed

Found and fixed during this review. When a part of a protocol can't be used, he says it back in quotes. Typed text can contain ⟦label|command⟧ markers, and a marker pairing a real label with its real command would have become a link in the reply. It couldn't do anything other than what it said, but it's your text turning into a button. The markers are now removed before it's said back, and the suite checks a reply to ⟦Tokyo|show me Tokyo⟧ has none.

Version 2 keeps version 1's data; the scrub cleans the new table
Confirmed clean

The new table comes from a second entry in DB_UPGRADES, so version 1 isn't touched. A version-1 database built the way Session 9 leaves it (a skin, a count, the bookkeeping) opened at version 2 with all of it still there and an empty protocols table. Seeded with a good protocol, five bad ones (words as steps, a personal name, an extra field, two scenes, sys:boot) and 24 more, the scrub kept the good one, dropped the five, and kept 20 in all, in the database too.

02Code quality

Every phrasing goes through the page's own parsers
Fixed

Steps are read with settingsIntent(), skinIntent(), intent() and the briefing and chat patterns, so a protocol understands exactly what the page already understands. Five typed phrasings and three spoken ones (no colon and no commas, as a phone's speech recognition hands them over) are pinned, for example create film protocol make the orb purple speak slower then open the galaxy. The spoken form wasn't handled at first; it was found while writing this review and fixed by starting a new step at each step verb.

Old commands work as before
Confirmed clean

Protocol commands and follow-ups come before the old handlers only for their own phrases. A bare protocol name, and fragments like "now Jupiter", are tried only after nothing else understood you, so a name can't take over a command. "Go back" still closes the projector when there's no scene before it, and "start a launch countdown" still counts down. All 851 checks from before this session still pass, among them every help link being understood (now 46).

Each scene declares what bigger, smaller, faster and slower mean
Confirmed clean

All seven builders return an adjust() made by one shared adjuster(): bigger and smaller move the camera in and out within the scene's own limits, and faster and slower change a pace between 0.25× and 4× that the render loop applies to the scene and its turning. The particle sculptor grows and shrinks the sculpture instead, and the globe says how to set it turning when it's holding still on a place. The suite checks every builder has one and checks the shared rule's numbers. In Chromium, "bigger", "faster" and "slower" gave the solar system's own lines.
