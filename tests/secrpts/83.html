The style was spoken as part of his line
Fixed

voiceBody() sent "<style>: <words>" as the one text to speak, and the model read all of it. It now sends the words alone as the text to speak, and the style, plus "Read the user's text aloud exactly as written, and nothing else. Never say these instructions.", as systemInstruction. If a model answers a system instruction with a 400, on the stream or the old request, the line is asked again with the words alone (never the style folded back in), and that instance stops sending it. The suite checks that no skin's style text is ever in the spoken part. The request shape is shared with record.mjs, so recordings will get the fix too. The log's first and ms now start before the call, so Google's wait before answering counts. A check advances a fake clock 1.5 s inside the call and sees it.

Broken copies (each failed): the style back in front of the words (jarvis-cloud, 4 checks); no retry without the style on a stream 400 (3); none on the old request (1); the refusal not remembered (1); the clock started after Google answers (1). jarvis-cloud: 244 checks, up from 234.
Lines kept on the device before the fix
Fixed

The device cache of fixed lines (kept, as you chose) held copies with the style spoken in them. Kept lines' addresses now carry VOICE_KEEP_V (live/v2/), so the old copies never match, and the first time the cache is opened, anything outside live/v2/ is deleted. The cache name is unchanged, so the service worker's list of caches stays as it is. A check seeds an old copy before the page loads, then sees the line voiced again and the old copy gone. Nothing personal is involved: the cache holds only the page's own fixed lines, as before.

Broken copies (each failed ownVoice): no version in the address (2 checks); the old copies never deleted (1). The first broken copy, which removed only one of the two purge calls, passed, because the other call (when a new line is kept) still deletes them, so both were removed for the real test. ownVoice: 136 checks, up from 132.
