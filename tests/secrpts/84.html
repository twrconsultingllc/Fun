Small change after review 83, in jarvis-test.html only, with no Vercel deploy. Switching skins, you couldn't tell which voice you were hearing. Every line he says aloud is now tagged with the voice that actually said it.

01Security

The tag is text only
Confirmed clean

The tag is set with textContent, never HTML, and its parts are fixed words, the skin's voice name from a fixed list (VOICE_NAMES, checked against the proxy's VOICES), a reason from the page's own list, and the device voice's name cut to 40 characters. The list of parts is kept in a data- attribute on the tag as JSON and read back only by the same function. Nothing is stored and nothing is sent anywhere. No new address, so the CSP is unchanged.

02Code quality

Every voice he uses is named, in order
Confirmed clean

The tags are GEMINI · CHARON (live), GEMINI · CHARON · SAVED (played from this device), RECORDED · CHARON, and BROWSER VOICE with the device voice's name when one is picked. A fallback adds the reason as before. An answer in more than one voice lists each in order, once per run. His own voice is tagged as it starts, so the tag shows while he speaks. Colours: plain (--label) for the browser's voice, green (--phos) for his own, amber for a fallback. Contrast against each theme's lighter background (--deep), computed: Jarvis 6.1 / 13.9 / 11.5, Morpheus 8.4 / 13.4 / 11.4, Stanley 7.6 / 5.7 / 7.6, hot-rod HUD 8.5 / 11.9 / 7.2, supercharged 8.7 / 10.3 / 12.6, all above 4.5:1. On Stanley, plain and amber are the same gold, so there the reason's words tell them apart. The tag appears wherever Web Audio exists, as in every current browser. The rest of the page suite runs in jsdom, which has none, so its checks of his words are untouched. ownVoice: 144 checks (up from 136); six earlier checks expected no tag and were changed to the tag each line should now carry.
