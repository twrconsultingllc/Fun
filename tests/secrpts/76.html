02Code quality

What it does
Fixed

The proxy's old rule (git diff --quiet HEAD^ HEAD -- .) only looked at the newest commit. If its folder changed in a commit whose build was skipped or rate-limited, and then something else was committed, the change would never deploy. That's what happened to the proxy today.

Fix: It now compares against VERCEL_GIT_PREVIOUS_SHA, the commit Vercel last deployed for that project and branch, falling back to the commit before when there isn't one. If that commit isn't in Vercel's shallow clone, git fails and the build goes ahead rather than being skipped.
Tests, and broken on purpose
Confirmed clean

tests/vercel-builds.test.mjs (13 checks, all passing) reads the three real files and runs their command with sh in a scratch git repository, in the project's folder, as Vercel does. A commit to another folder is skipped, and so are the other two projects when one folder changes. A change still counts when a later commit came after it. A previous commit missing from the clone builds, a merged pull request is judged on all its commits, and it works with no previous deploy known. With the old command put back in all three files, two checks failed. The proxy's suite still passes (123).
