01Security & privacy

Short-term memory never reaches storage
Confirmed clean

What you tell Jarvis ("my dog is Rex", "I'm going to the beach") lives in one in-memory array. The memory section of the script has no call to store(), unstore(), saveLearned() or saveSettings(), and the suite checks that by slicing the source. After telling five things and a name, every localStorage value is searched for them, and none is there. A reload (a new page given exactly what the old one left in storage) answers "what's my dog's name" with "you haven't told me".

A taught phrase could have smuggled a memory into storage
Fixed

Found while building. If Jarvis didn't understand "blorp" and you answered "I meant my cat is Tom", the old teach flow would have saved "blorp" → "my cat is Tom" in jarvis-learned, which is stored. A memory statement or question is now never learned: Jarvis remembers it for the visit and says so, and the suite checks that blorp isn't learned and Tom isn't stored.

New keys: fixed choices only, rebuilt on every load
Confirmed clean

STORE_KEYS grows from four to six: jarvis-settings and jarvis-streak. Settings are four fields, each one of a fixed list in SETTING_CHOICES, so there is no free text in them. The scrub rebuilds both keys from their fixed shape, so a hostile value ({"color":"blue","name":"Tony","scene":"<img src=x onerror=…>","speed":"ludicrous"}) comes back as {"color":"blue"}, a key with nothing valid is deleted, and a clean key is left byte for byte. All 108 combinations of colour, units and scene (with a speed) were run through personal(), and none is refused. localStorage.setItem still appears once, in store().

The streak date and personal()
Fixed

Review 54 left this open. Decided: personal() stays strict, and the date is stored as separate numbers, {"days":3,"y":2026,"m":10,"d":10}. An ISO date was checked first: 2026-10-10 reads to the phone-number rule as eight digits with separators, so it would be refused. The separate-numbers form passed personal() for 800 consecutive days from 2026-01-01, and at counts of 1, 99, 999 and 9999. The count stops at 9999, since five digits would trip the long-number rule.

Labels and drifting phrases are text, not markup
Confirmed clean

Memory core labels show what you typed ("remember that …", taught phrases). They're set with textContent, and the page has no innerHTML at all (grep: 0). While dreaming, phrases are drawn on the orb's canvas with fillText. The memory core is the suit's callout pattern: buttons in a #mem-labels layer, laid out by layoutCallouts() and removed in dispose(). In Chromium, nothing of #mem-labels was left after "close".

persist() could have shown Firefox users a prompt
Fixed

Found in review. navigator.storage.persist() is silent in Chrome and Edge, but Firefox asks the user with a permission prompt. The plan called for it in Chrome and Edge only, so the call is limited to Chromium (navigator.userAgentData with a Chrome or Edge brand), the same test the wake word uses. It's asked once per visit, only after something is saved, and skipped when storage is already persisted. Each of those cases has a check.

The build plan update
Confirmed clean

jarvis/build-plan.html gets Session 7's badge in the session and in the index, its notes, a link to this review, and two corrections to the map (the suite's count, buildMemory in the scenes list). It uses existing classes only, with no script and no inline colour. A parser pass found the tags balanced and every # anchor and file link resolving.

No new host, no new permission
Confirmed clean

The CSP meta tag is unchanged and still connect-src 'self'. Nothing new asks for the camera, mic or location. Crushing a star with a fist uses hand control's existing camera, which follows its existing rules.

Labels pointed at Infinity on the first frame
Fixed

The first Chromium run logged four SVG errors (x1: Expected length, "Infinity"). Before the camera's first move, the core star sits exactly at the camera and projects to infinity. place() now skips a frame whose positions aren't finite. The rerun had no errors.

What can't be checked here
Open

Whether short-term memory feels useful when it forgets on close, and whether 3 minutes is too soon to dream, are for you to judge on the live test copy. Whether Chrome grants persist() depends on how much you use the site, so a test can only confirm that it was asked. Safari's 7-day wipe can't be detected: Jarvis says "this looks like my first time on this device" whenever nothing is stored. Units only change the few facts that give measures (the Moon, the Sun, Earth, Everest, the suit, Neptune).
