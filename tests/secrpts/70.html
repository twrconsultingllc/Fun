02Code quality

Worker errors are strings, so the checks never matched
Fixed

The engine runs in jarvis/llm/worker.js. When something fails there, WebLLM 0.2.85's handler sends back err.toString() (message kind "throw" in web-llm.js), and the page-side engine rejects with that string. So the page receives "AbortError: Failed to execute 'mapAsync' …", a string with no name or message. The check in askBrain() tested failed.name+' '+failed.message, which for a string is "undefined undefined". It never matched, so the dead engine stayed on, and every later question failed the same way. The install path had the same bug: a string error never matched its half-precision or out-of-memory lines, so both would have said "check your connection".

Fix: One helper, errText(), gives an error's text in either shape: a string as it is, an Error as "name: message". The install path, the recovery check and the text "why?" reads out all use it.
