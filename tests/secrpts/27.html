Review #27 — snake.html (rival spawn fix)

The snake-dom suite failed about once in eight full runs, on "at least one rival snake spawns at level 1". That turned out to be a real bug in the game, not a flaky test. This change fixes how buildEnemies() and buildObstacles() place things, and makes the test check 300 builds instead of one. It only touches the page's script logic: no new markup, links, styles or outside resources.

01Correctness

About 1 level-1 game in 20 had no rival snake
Fixed
At level 1 on the default difficulty, enemyCountForLevel() asks for 1 rival. buildEnemies() picked one random cell, and if that cell was inside the clear area around the player's start (11 × 7 = 77 of the 1,408 possible cells, about 5.5%), it moved on with no retry. In a jsdom simulation of 3,000 level-1 builds with the old code, 146 (4.9%) had no rival, and the average was 0.951 rivals against 1 expected.
Fixed: each rival now gets up to 60 placement attempts. The same 3,000-build simulation gives 0 missing rivals and an average of exactly 1.000.
A rival's tail could land on obstacles, other rivals or the start area
Fixed
spawnEnemyAt() checked only that the body stayed on the board. The start-area check looked at the head alone, and nothing checked the two tail cells against what was already placed. In the old code, 39 of 3,000 level-1 builds had a rival body inside the start area. At level 6, 2,000 builds gave 80 rival-on-obstacle and 13 rival-on-rival overlaps.
Fixed: spawnEnemyAt() takes a blocked test, and buildEnemies() passes one that rejects any occupied cell or any cell in the start area, for every segment. After the fix, both simulations show 0 of each.
Crossing walls were stored twice
Fixed
When two random walls crossed, buildObstacles() pushed the shared cell twice. It drew and played the same either way, but at level 6, 168 of 2,000 builds had a duplicate wall cell, which made the overlap check unreliable.
Fixed: a Set skips a cell that's already a wall. After the fix, the level-6 simulation shows 0 builds with any overlap of any kind.
The test couldn't catch the bug
Confirmed clean
The old assertion checked one random build, so it passed about 95% of the time even with the bug. It now builds 300 times at level 1 and 300 times at level 6, where obstacles appear. Each build must have exactly enemyCountForLevel() rivals, no rival segment in the start area, and no two things on one cell. With the old code's 4.9% miss rate, 300 builds would all pass with probability 0.951300, about 3 × 10−7. The full suite passed 6 runs in a row, 1244 passed and 0 failed each time.

02Security

No new surface
Confirmed clean
The diff changes only placement logic inside the existing inline script. There are no new DOM writes, no innerHTML, no storage, no network access, no new markup, links or styles, and the page's CSP and referrer meta tags are unchanged. The retry loop is capped at 60 attempts per rival and at most 4 rivals, on top of freeCell()'s existing 600-attempt cap, so a crowded board can't hang the page.
This is a static snapshot, not a live check. Placement was checked by simulating level builds in jsdom through window.__snake, not by playing the game in a browser. See 26.html for the previous review.
