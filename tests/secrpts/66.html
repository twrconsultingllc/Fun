Review #66 — J.A.R.V.I.S. Session 14: the full brain

Say "Jarvis, install your full brain" and, where the browser has WebGPU, the test copy offers to download a small open language model, Qwen3-0.6B, from this site: 351.5 MB, kept by the browser. Once it's running, anything nothing else understood goes to it. It answers in a fixed format and can only pick commands from the protocols' list, which the page checks before running anything. Facts come from the knowledge pack, and its own guesses are labelled. Nothing it says is stored.

01Security and privacy

CSP unchanged: no new outside host
Confirmed clean

The suite still pins the whole CSP string to what it was before Session 8. WebLLM, its worker, the engine and the weights all come from jarvis/llm/ on this site. The page has no Hugging Face, raw.githubusercontent.com or binary-mlc-llm-libs address (grep, and a suite check), and the model record passes only addresses built from location.href. The worker is same-origin, so script-src 'self' covers it, and the WebAssembly needs only the 'wasm-unsafe-eval' that was already there. In Chromium, the request log for the whole step held nothing from outside the local server, and no CSP violation was logged.

WebLLM wrote to localStorage
Fixed

The first Chromium run failed "no localStorage written". WebLLM bundles the loglevel library, and every engine started on the page's main thread calls log.setLevel(), which saves loglevel = WARN in localStorage (or, failing that, a cookie). It isn't personal, but the test copy never writes localStorage (Session 9), and it shares that storage with jarvis.html. The CSP can't stop it, and patching the vendored file would break its pinned hash.

Fix: The engine now runs in a worker, jarvis/llm/worker.js (our own few lines, pinned by hash). A worker has no window, so loglevel persists nothing. The page never passes a log level, which would make WebLLM's main-thread side save one. The suite checks the engine is only ever created through CreateWebWorkerMLCEngine with that worker, and a copy of the page creating it on the main thread fails that check. In Chromium, after the page's own loader ran the real WebLLM, localStorage was empty.
Nothing the model says or hears is stored
Confirmed clean

The suite reads the full brain's code, comments removed, and fails if it calls store() or save() or touches localStorage, indexedDB or a transaction. Copies of the page that wrote the conversation to localStorage, or a count of it to meta, each failed that check. After pancakes, the Eiffel Tower, Peru, a pick and a failure, the jsdom database and localStorage held none of the words. In real IndexedDB, before and after differed only in usage counts and the public knowledge pack, which the first fact question copies in, as in Session 13. The one-place-that-saves checks pass unchanged: no localStorage write call in the page, and one 'readwrite' transaction, in flush(). A reload starts with the brain off and no conversation.

What it's given is in memory only
Confirmed clean

Each question carries the skin's fixed instructions, the knowledge pack's answer when the sentence names something in it, this visit's short-term memories and your name (both already in memory only, Sessions 7 and 11), and at most the last three exchanges, kept in full.turns. Nothing leaves the device: the model runs on the graphics chip. "What do you save" says the conversation is in memory only, and that the model files are the browser's cache.

Every pick is checked, and nothing destructive is on the list
Confirmed clean

BRAIN_PICKS is every protocol step ID except the 30 waits. The suite checks that none deletes, forgets, resets or reboots (the meaning module's DESTRUCTIVE test), none starts the camera or the mic (asksFirst), and each is a real STEPS ID. checkPick() runs only an exact match, through the same path as a protocol step. Invented (launch:missiles), destructive (forget:everything), protocol:delete, wait:5, cmd:scan, sys:boot and a two-in-one lookalike were each refused, with nothing changed and the refusal said. Accepting any STEPS ID, or not checking at all, made those checks fail (1 and 8 failures).

Its words can't become markup or a command button
Confirmed clean

Answers reach the chat through add(), which builds text nodes; the page still has no innerHTML. cleanSay() also removes ⟦ ⟧ < >, backticks and markdown, and cuts the answer to a sentence or two. A reply carrying <img onerror> and ⟦delete movie night⟧ produced no element and no button, only plain words. A copy without the clean-up failed. The "FULL BRAIN" tag is built with textContent.

The weights workflow
Confirmed clean

.github/workflows/jarvis-llm.yml is run by hand only, uses the same SHA-pinned actions/checkout and actions/setup-node as the other workflows, keeps no token in git config while downloading, and gives GITHUB_TOKEN only to the commit step. Its inputs are choices and reach the shell through env, never pasted into a command (the suite checks all of this). fetch-model.mjs downloads only from huggingface.co at a pinned 40-character commit. It refuses any file name that isn't flat and plain, so nothing can be written outside the model's folder, and it checks every SHA-256 against models.json. The dry run against tests/fixtures/jarvis-llm/ runs first and must refuse eleven bad cases. The suite runs it too.

The licence: mlc-ai's build states none of its own
Fixed

The first pin runs refused both models, as specified: mlc-ai/Qwen3-0.6B-q4f16_1-MLC (and the Qwen2.5 build) has no licence tag and no licence line on its card. Its card names base_model: Qwen/Qwen3-0.6B.

Fix: Put to the user, who chose "inherit from base". A converted model that states no licence of its own is accepted only when its card names exactly the pinned base model. That base must say apache-2.0 in its tag and on its card, and its LICENSE must be the Apache License 2.0 (all three hold for Qwen/Qwen3-0.6B at c1899de). Anything a model does state must also be apache-2.0. The dry run gained a model that inherits and passes, and one naming another base that's refused. The GPL-base case now reaches the base check, not the name check. The base model's licence is committed beside the weights.
The engine's repository has no licence file
Open

Qwen3-0.6B-q4f16_1_cs1k-webgpu.wasm comes from mlc-ai/binary-mlc-llm-libs, pinned to commit 025bcaf, which has no licence file (its GitHub record shows none). It's MLC LLM's compiled output, and MLC LLM and Apache TVM are Apache-2.0. The same team publishes it for exactly this use: WebLLM's own model list loads it from there. Every WebLLM site does the same, so this is low risk, but it isn't written down anywhere. Noted in jarvis/llm/README.md, for the user to decide whether that's enough.

02Code quality

The real model can't run in this container
Open

Headless Chromium here has WebGPU through SwiftShader's software adapter, but that adapter has no shader-f16, which the q4f16 build needs. So no real answer from Qwen3 could be produced or timed here. What was checked with the real files: the page reads the adapter correctly and says the chip can't do half precision, fetching nothing. The page's own loader starts WebLLM 0.2.85 in its worker, which checks the config and engine hashes and stops at shader-f16 before reading the tokenizer or a single weight. WebLLM's own model list names this exact engine for this model, from the v0_2_84/base set the library was built for. Real speed and the quality of answers on a PC and a phone are for the user to judge, as the plan says.

Fixed

Fix: Advice words are no longer in ABOUT_WORLD. Questions starting with who, what, when, where, which, why, how, is, are, does, can and the like still are, unless they're about him. Pinned both ways.

Fixed format, thinking off, guesses labelled
Confirmed clean

Every request sets extra_body: {enable_thinking: false}, streams, and asks for at most 160 tokens. Any empty <think> block is dropped. An answer without a SAY: line is refused and not counted. "From memory, I may be wrong:" goes on an answer about the world with no pack facts behind it, or one that adds a number the facts didn't have. Small talk about him has no label. Guesses not labelled, numbers not checked, or the small-talk exemption widened to any "chat" each failed the checks.

Failures fall back cleanly
Confirmed clean

An error before it answers says so, and the brain stays on. A second question while it's still streaming gets "I'm still thinking". The graphics chip lost halfway through turns the brain off, with "I'm back on my standard brain", and the next miss is the usual line. A 45-second limit interrupts a runaway answer. "Turn off your full brain" unloads it and ends the worker.
